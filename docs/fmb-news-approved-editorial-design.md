# FMB News approved editorial design contract

This is the current visual source of truth for FMB News / Filipino Media Bulletin. It supersedes earlier plum/gold mobile-home directions and any instruction that forbids the approved editorial bottom dock.

## Product boundary

FMB News remains one application in this repository and one Cloudflare deployment under `/news/`. Do not create a second app, duplicate content source, Vercel deployment, or FMB-Ecosystem copy.

The redesign is presentation and information architecture work. Preserve the current article renderer, archive, CMS integration, editorial verification, structured data, sitemap/RSS, PWA, personalization, passwordless reader session, push logic, Fact Check gate, Explainer library, horoscope and crossword.

## Approved desktop visual

Desktop is a premium newspaper-style publication, not a dashboard and not a purple marketing landing page.

- warm ivory editorial paper
- near-black ink
- signal red accent
- large serif `FMB NEWS.` masthead with a red period
- `FILIPINO MEDIA BULLETIN` subtitle
- restrained rules and whitespace rather than card chrome
- real current lead story with image, headline and deck
- World, Sports and Entertainment editorial rail
- FMB News, FMB Worldwide, FMB Daily Brief, FMB Fact Check and FMB Explainer modules
- Entertainment, founder/About and newsletter sections
- System / Light / Dark appearance remains supported

The visual authority for the desktop Home is `public/assets/css/fmb-news-editorial-reference-v2.css`. It is injected last on `/news/` through the content-hashed brand system. Do not add a second homepage override stylesheet.

## Approved mobile visual

Below 700px, FMB News should feel like a refined native news app with Apple-like restraint: clear hierarchy, safe-area awareness, large touch targets, minimal chrome, fast readable transitions and no decorative clutter.

The approved mobile composition is:

1. newsroom-black sticky header
2. hamburger on the left
3. centered white serif `FMB NEWS.` with red period and small `FILIPINO MEDIA BULLETIN`
4. search on the right
5. compact text rail: `Home`, `World`, `Sports`, `Briefing`, `Fact Check`
6. current real lead-story image and headline, never a fictional mock headline
7. World, Sports and Entertainment story rows
8. Latest News rows with real images
9. Daily Brief / Explainer feature modules
10. fixed safe-area-aware dock: `Home`, `World`, `Sports`, `Briefing`, `Menu`

The fixed dock in this approved design is intentional. Do not remove it because an older handoff said “no fixed bottom navigation.” The obsolete dock classes remain forbidden; the only approved dock is `.fmb-editorial-mobile-dock` generated by the shared mobile shell.

The final mobile visual authority is `public/assets/css/fmb-news-mobile-navigation-lock.css`, bundled last into the content-hashed mobile system. Shared mobile behavior is owned by `public/assets/js/fmb-news-mobile-global.js`.

## Content integrity

Design references are visual references only. Never hardcode a fictional breaking event, headline, number, reader count, alert or source to make the interface resemble a mockup.

Home story content must be selected from the published FMB News corpus. Every published JSON story must continue to produce its canonical article route. The existing editorial-production verifier and canonical verifier must fail the build if published routes disappear.

## Architecture rules that prevent future conflicts

- `scripts/render-home-experience.mjs` is the sole authored Home renderer.
- `scripts/render-news-routes.mjs` owns archive and structured article routes and must not become another Home renderer.
- `scripts/render-network-shell.mjs` owns shared publication chrome on internal routes.
- `scripts/apply-brand-system.mjs` owns content-hashed appearance assets and installs the approved editorial reference last on Home.
- `scripts/hardfix-mobile-first-site.mjs` assembles one content-hashed mobile stylesheet in explicit order.
- `fmb-news-mobile-navigation-lock.css` stays last in that mobile bundle.
- Do not restore deleted compatibility/hardfix renderers or add another late dist mutation for the same UI.
- Do not replace content-hashed asset versions with hand-maintained date strings.
- Do not merge an old design branch wholesale into current main. Port only the required visual behavior onto the current architecture and re-run all gates.

## Required quality gate

Before any design change is merged or deployed:

- `npm run build`
- `npm run verify`
- `npm run test:mobile:browser`
- rendered phone QA at representative iPhone widths
- desktop regression QA
- no horizontal overflow
- no missing published article route
- no broken canonical URL
- no duplicate Home renderer, masthead, ticker, PHT clock, newsletter form or mobile dock
- accessible focus behavior and reduced-motion support

A passing build without rendered QA is not design approval.
